## 性能审查（对正常网页浏览的影响）
- 产出 `性能审查报告.md`。结论：无可感知拖累。无 setInterval/轮询、content script 无 fetch、无 webRequest 拦截。
- 普通站点高频路径只有 unclip-main.js:42-51 的 blocker（document capture 的 keydown/keyup），微基准 100 万次 47ms ≈ 47ns/次，100 字符打字 9.4μs，可忽略。
- MutationObserver 仅域名命中的 3 个站点创建（core.js:91-93 的 _matchingEnabled 过滤），普通站点 0 个；CSS 注入仅白名单站点。
- 值得优化的点（未改代码）：unclip-main/bridge 的 all_frames:true 让每个 iframe 都注入 9 个监听+1 次 storage 读（manifest.json:48,54）；非白名单也注册 6 个 capture 监听；控制台日志噪音；考试宝全量 observer（已 rAF 合帧）；background 每条 complete 发 2 条消息其中 1 条仅为日志。
- 验证方式：静态逐行审查 + headless Chrome 微基准；真实浏览器 A/B 录制列为需用户实测。

## 书签页侧栏：高度 + 标签组默认折叠/状态记忆
1. 侧栏折叠后显矮：`bookmarks.css` 给 `.sidebar` 加 `min-height: calc(100vh - 110px)`（与 max-height 同值），折叠状态下也铺满视口；窄屏媒体查询覆盖 `min-height: 0` 保留原 220px 行为。
2. 标签组"只显示 3 个"：代码无截断（`groups.forEach` 渲染全部），真实原因是展开态下每组若干标签把后续组挤出滚动可视区（截图里第 3 组已被底部裁切）。修法：
   - 标签组默认折叠：折叠模型由 `collapsedGroups`（内存 Set，默认展开）改为 `expandedGroups`（默认空=全折叠），新增组也默认折叠。
   - 折叠状态持久化：新 key `bm_expanded_groups`（localStorage），`saveExpandedGroups()` 在 caret 切换时调用；与文件夹已有的 `bm_collapsed_folders` 一起覆盖"所有展开折叠都记住"。
   - `watchGroups()` 增加 `chrome.windows.onFocusChanged` 刷新，跨窗口的组切回时同步。
   - 日志增强：`[bookmarks] 全部标签组:` 每条带 `windowId` + 成员数，便于核对 API 是否真的只返回 3 个（若日志 N>3 而界面仍少，属显示问题；若 N=3 需用户确认浏览器侧实际组数）。
