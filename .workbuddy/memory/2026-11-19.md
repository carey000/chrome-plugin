- 用户反馈：书签页「标签组」面板只显示 2 个组（全/美），但浏览器标签栏肉眼可见约 10 个组（performance/训练师/xlx/学/TW/Code/全/美/日/V）。用户确认截图2 是浏览器标签栏的 tab group，目标是列全所有标签组。

## 「已保存的标签组」API 调研（docs/Chrome已保存标签组-扩展API调研.md）
- 用户后续截图（菜单顶部「创建新标签页分组 Alt+Shift+P」+ 14 个彩色组：美/Code/训练师/xlx/学/performance/TW/V/全/SEO/Schema/日/dev/登注）证实：这些是 Chrome **Saved Tab Groups（已保存的标签组）**，即「关闭组后保存到书签栏/菜单」的组，不是当前打开的组。上次「分窗口查询」方向错了——query({}) 本就查所有窗口，真正原因是 saved/closed 组 API 层面就不返回。
- 调研结论（有官方文档/源码 README/issue 依据）：saved groups 基于 Chromium sync 存储层（components/saved_tab_groups），不是书签节点（书签栏只是显示入口）；显示位置在书签栏 ≠ 存成书签；书签 HTML 导出不含它们。chrome.tabGroups API（字段 id/title/color/collapsed/windowId/shared，方法 get/query/move/update）无任何 saved/pinned/closed 读写能力；Chrome 137 的 shared 字段是「共享组」不是「已保存组」。W3C webextensions issue #715（2024-10 提出）至今未实现；Chromium issue 40174035/327629161 未解决。
- 可行方案：A 手动点开保存组（打开期间扩展可见，可做快照）；B 用书签文件夹替代（项目已有书签模块）；C 常驻监听 onCreated/onUpdated 自建存档（只能记录安装后新建/打开的，历史 14 个补不回）；D native messaging 读 profile 磁盘（不推荐）；E 等 API。实际可行 A+B。
- 本次未改代码，只产出调研 md；bookmarks/bookmarks.js 上次的「分窗口查询」改动是否回滚待用户确认。临时放大图 _imgwork/_vzoom.png 已清理。
