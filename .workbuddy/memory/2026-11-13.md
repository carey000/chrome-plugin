## 修复临时回归脚本的日期硬编码（非产品 bug）
- **现象**：`nt-header-test.js` 有一条断言写死「2026-11-12 农历为十月初四」，跨到 11/13 后产品正确输出「十月初五」，断言必然失败。

- **修复**：断言改为在宿主侧用 ICU 中国日历独立算出当天的 `month + LUNAR_DAYS[day-1]`，再比对 `dateText.endsWith(expectedLunar)`，不再硬编码日期。只改 `%TEMP%/nt-header-test.js`，产品代码零改动。
- **经验**：涉及「当前日期 / 时间」的回归断言不能写死具体值，否则每次跨天都会误报；应独立算期望值或 mock 固定时钟。

## 气泡右对齐 + 修复「刷新点了没气泡」（重要 bug）
- **需求**：① 气泡定位以按钮右边为基准对齐；② 「刷新也需要气泡」。
- **② 的真实根因（不是漏接气泡）**：集合头「刷新」是 `icon-btn` 纯 SVG（`refresh.innerHTML = REFRESH_ICON`），真实浏览器里点击的 `event.target` 是 `<svg>/<path>` 而非 button；`bindConfirmDismiss()` 原本只判 `target === confirmAnchor`，于是**同一次点击冒泡到 document 时把刚打开的气泡立刻关掉**。「恢复全部」「删除」是文字按钮、target 就是自身，所以正常。上一轮 vm mock 的 `fire()` 写死 `target: this`，正好掩盖了这个差异。
- **修法**：`bindConfirmDismiss()` 改为 `target === confirmAnchor || confirmAnchor.contains(target)` 才视为「非外部点击」；`askConfirm()` 改为右对齐：先 `pop.hidden = false` 再取 `offsetWidth`（hidden 时为 0），`anchorRight = rect.right || rect.left + width`，`right = min(anchorRight, vw - 8)`，`left = max(8, right - width)`。气泡宽 240px（全局 `box-sizing: border-box`，即含 padding/border），CSS 未改。
- **页面共 3 个「刷新」**：集合头 SVG（已接气泡，本次修好）、右栏 Open Tabs 顶部 `#refreshTabsBtn`（`scheduleRefresh()`，纯读取视图）、页面历史 `#historyRefreshBtn`（history.js，纯读取）。后两个**未加气泡**，属非破坏性视图刷新，按「只改点名部分」不擅自扩大；已在回复里请用户确认。
- **测试**：`nt-confirm-pop-test.js` mock 补 `right` 字段 + `fire('click', {target: svgPath})` 模拟 SVG 子节点；定位断言 `left:100px` → `left:120px`（right 360 - 240），新增右边缘重合、贴右缘/贴左缘夹取、SVG 子节点不被误关等 6 项（36 → 42）。**17 组回归全部 ALL PASS，合计 687 项断言**。
- **教训**：涉及 `event.target` 与元素包含关系的逻辑，vm mock 必须能模拟子节点 target，否则文字按钮通过 ≠ 图标按钮通过。
