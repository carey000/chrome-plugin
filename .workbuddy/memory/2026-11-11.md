## 第二轮：按站点拆分为多文件（方案 A）

- 架构决策：按「站点」而非「功能」拆分；空标签页 / todolist 属扩展页面组件（newtab / popup / side panel），不进 `content/`。
- MV3 约束：content_scripts 多文件按 js 数组顺序注入**同一 isolated world**、共享 window，不支持静态 import；统一挂 `window.AutoBoat`。
- 结构：`src/config.js`（不变）→ `content/core.js`（flags / 工具 / SiteHandler / FeatureManager / 消息监听）→ `content/sites/{kuxueyuan,baidu,kaoshibao}.js`（各自注册到 `AB.sites`）→ `content/boot.js`（按 config + 注册表实例化，必须最后）。
- 消息监听放 core.js，通过 `AB.manager` 延迟引用；manager 由 boot.js 同步创建，避免顺序依赖。
- 删除原 `content/content_script.js`（640 行合并版）。manifest 的 js 数组改为 6 个文件按序。
- 新增站点只需 3 步：加 `sites/xxx.js` 并注册同名类 + `config.js` 加一条 + `manifest.json` 的 js 加一行；core / boot 不用动。
- 验证：8 个 JS 全过 `node --check`；用 vm 按 manifest 真实顺序模拟注入，注册 / 装配 / 域名匹配 / 开关 gating / 热切换 / 消息链路全部通过。
- 站点类代码为逐行搬运，未改任何站点逻辑；popup、background、config.js 本轮未动。
- 遗留：`manifest.json` 仍带 `//` 注释（非合法 JSON），已请用户确认重新加载是否报错，未擅自删除。
